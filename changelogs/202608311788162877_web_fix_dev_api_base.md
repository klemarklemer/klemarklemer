# [web] fix: Let the dev server reach the API again

**Date:** 2026-08-31  
**Timestamp:** 1788162877  
**Type:** `[web]` bug fix  
**Service:** `apps/web`

---

## Summary

`npm run dev` served a console that could not load any data, with nothing in the
UI to say why.

`vite.config.ts` injects `VITE_API_BASE` as `process.env.VITE_API_BASE_URL || ''`,
so with no env var set the value is the empty **string**. `client.ts` then guarded
it with `?? '/api'`, which only fires on null or undefined — an empty string passes
straight through. Every request went to `/v1/...` on the dev-server origin, while
the proxy that forwards to the API is mounted at `/api`:

```
GET /v1/claim       -> 404   what the app asked for
GET /api/v1/claim   -> 200   what the proxy is configured for
```

Both halves are now consistent: the fallback in `vite.config.ts` is `'/api'`, and
`client.ts` uses `||` so an empty value cannot defeat it either.

## Verification

- `npm run dev` with no env var: injected base is `/api`, `GET /api/v1/claim`
  returns 200 through the proxy with real rows from a local API.
- Deploy path unchanged: `npm run build` with the `VITE_API_BASE_URL` the Pages
  workflow sets still bakes that Cloud Run URL into the bundle.
- `npm run typecheck` and `npm run test` pass.
